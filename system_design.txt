===============================================================================
                    MEDQUAD MEDICAL CHATBOT
                       SYSTEM DESIGN
===============================================================================

Project: MedQuAD Medical Question-Answering Chatbot
Architecture: Modular Machine Learning System
Initial Modality: Text / Tabular Medical Q&A
Cloud Platform: AWS SageMaker AI
Application: Streamlit
Initial Model: FLAN-T5


===============================================================================
1. DATA INGESTION ARCHITECTURE
===============================================================================

PURPOSE
-------

The data-ingestion layer is responsible for discovering and classifying raw
data before it enters the machine-learning pipeline.

The initial MedQuAD project uses tabular question-answer data. However, the
architecture is designed so additional medical data sources can be introduced
in future versions without redesigning the entire ingestion system.


SUPPORTED / PLANNED DATA TYPES
------------------------------

Current:

    CSV                     Tabular data
    XLSX                    Tabular data

Future:

    JSON                    Structured / semi-structured data
    Parquet                 Structured tabular data

    PDF                     Document
    TXT                     Document
    DOC / DOCX              Document

    JPG / JPEG              Image
    PNG                     Image
    DICOM (.dcm)            Medical image


IMPORTANT:

Supporting a file type in the architecture does NOT mean that the loader must
be implemented in Version 1.

For the current MedQuAD project, only the loaders required by the available
dataset need to be implemented.

The ingestion system separates:

High-Level Flow

                            |
                            v
                      load_data.py
                            |
                            v
                  Discover Raw Files
                            |
                            v
                    Classify Files
                            |
             +--------------+--------------+
             |              |              |
             v              v              v
          TABULAR        DOCUMENT         IMAGE
             |              |              |
             v              v              v
        Tabular Loader  Document Loader  Image Loader
             |              |              |
             v              v              v
         DataFrame         Text        Image / Array


DESIGN RULE
-----------

    load_data.py
          =
    WHAT DATA EXISTS?


    loaders/
          =
    HOW DO WE READ THAT DATA?


===============================================================================
4. load_data.py
===============================================================================

PURPOSE
-------

Discover and classify raw files.

This module should NOT contain detailed parsing logic for every supported
file format.


INPUT
-----

The module accepts either:

    1. A single file

       Example:

       data/raw/medquad.csv


    2. A directory

       Example:

       data/raw/


    3. A directory containing nested subdirectories

       Example:

       data/raw/
       |
       +-- medquad/
       |   |
       |   +-- medquad.csv
       |
       +-- external/
       |   |
       |   +-- questions.json
       |
       +-- documents/
       |   |
       |   +-- guidelines.pdf
       |
       +-- imaging/
           |
           +-- MRI/
               |
               +-- scan001.dcm


RESPONSIBILITIES
----------------

load_data.py should:

    [1] Accept an input path

    [2] Check whether the path exists

    [3] Determine whether the path is:
            - File
            - Directory

    [4] Recursively search directories and subdirectories

    [5] Discover raw files

    [6] Inspect file extensions

    [7] Classify discovered files

    [8] Report unsupported formats

    [9] Provide discovered files to the appropriate loader


IT SHOULD NOT
-------------

load_data.py should NOT:

    X  Clean data

    X  Remove duplicates

    X  Perform EDA

    X  Create embeddings

    X  Perform feature engineering

    X  Train models

    X  Parse MRI images

    X  Contain model-specific logic

        |

        |
        +-- medquad.csv
        |
        +-- guidelines.pdf
        |
        +-- external/
        |      |
        |      +-- medical_data.json
        |
        +-- imaging/
               |
               +-- scan001.dcm


All supported files are discovered even when they are located inside
subdirectories.


===============================================================================
6. FILE CLASSIFICATION
===============================================================================

Files are classified according to their format and expected modality.


    EXTENSION                  CLASSIFICATION
    --------------------------------------------------

    .csv                       Tabular

    .xlsx                      Tabular

    .json                      JSON

    .parquet                   Parquet

    .pdf                       Document

    .txt                       Document

    .doc                       Document

    .docx                      Document

    .jpg                       Image

    .jpeg                      Image

    .png                       Image

    .dcm                       Medical Image

    Unknown                    Unsupported


Unknown files should NOT cause the entire ingestion pipeline to fail.

Instead:

                         Unknown File
                              |
                              v
                         UNSUPPORTED
                              |
                              v
                    Record / Report File


===============================================================================
7. loaders/ DIRECTORY
===============================================================================

PURPOSE
-------

The loaders directory contains file-format and modality-specific reading logic.

This prevents load_data.py from becoming one large module containing logic
for CSV, JSON, PDF, Word, Parquet, images, DICOM, and future formats.


Architecture
------------

                       load_data.py
                            |
                            v
                       Classification
                            |
          +-----------------+-----------------+
          |                 |                 |
          v                 v                 v
       Tabular           Document           Image
          |                 |                 |
          v                 v                 v
 tabular_loader.py  document_loader.py  image_loader.py

8. tabular_loader.py
===============================================================================

STATUS:

    VERSION 1 - REQUIRED


PURPOSE
-------

Load conventional tabular datasets.


INITIAL FORMATS
---------------

    .csv
    .xlsx


INPUT
-----

    File Path


PROCESS
-------

    medquad.csv
         |
         v
    tabular_loader.py
         |
         v
       Pandas
         |
         v
      DataFrame


OUTPUT
------

    Pandas DataFrame


RESPONSIBILITIES
----------------

    - Read CSV files

    - Read Excel files

    - Handle file-reading errors

    - Return a DataFrame

    - Perform basic structural validation


NOT RESPONSIBLE FOR
-------------------

    - Missing-value treatment

    - Duplicate removal

    - Text normalization

    - Feature engineering

    - Model training


Those operations belong to later pipeline stages.

16. NOTEBOOK INTERFACE
===============================================================================

The notebook should NOT manually manage recursive directory scanning.

The goal is to expose a simple interface such as:


    from src.data.load_data import discover_data

    raw_files = discover_data("../data/raw")


The notebook therefore focuses on:

    - Experimentation

    - Data inspection

    - Visualization

    - Model development

    - Evaluation


while reusable ingestion logic remains inside src/data/.

===============================================================================
19. KEY ARCHITECTURAL RULE
===============================================================================

The central rule of the data-ingestion architecture is:


    load_data.py
         |
         +--> "WHAT DATA EXISTS?"


    loaders/
         |
         +--> "HOW DO WE READ THAT DATA?"


This separation allows the current MedQuAD chatbot to remain lightweight while
providing clear extension points for:

    - Additional medical Q&A datasets

    - JSON and Parquet data

    - Medical reference documents

    - External knowledge sources

    - Medical images

    - DICOM / MRI data

    - Future multimodal models
